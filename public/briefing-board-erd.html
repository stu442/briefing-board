브리핑 보드 ERD

현재 앱에서 실질적으로 쓰는 핵심 테이블은 briefings 와 market_prices 두 개야.
JSON 문서는 브리핑 본문용 canonical source이고, SQLite는 메타/시계열 조회에 최적화되어 있음.

핵심 관계

  • • 두 테이블 사이에 DB foreign key는 없음
  • • 앱 레벨에서 같은 날짜/심볼 문맥으로 함께 사용함
  • • `briefings`는 페이지 단위
  • • `market_prices`는 자산-날짜 단위

왜 분리했냐

  • • 브리핑 본문은 JSON이 merge 하기 쉬움
  • • 메타 조회는 SQLite가 빠름
  • • 차트 데이터는 행 단위 정규화가 맞음
  • • 하나의 날짜 페이지 + 별도 시계열 분석 둘 다 만족

향후 확장

  • • `market_events` 테이블 추가 가능
  • • 읽음 상태용 `briefing_reads` 가능
  • • 관심자산 설정용 `watchlists` 가능
  • • 하지만 지금 v1은 2테이블이면 충분함
