민수 브리핑 생성 흐름 + AI 마켓 코멘트가 들어갈 위치

이 다이어그램은 현재 브리핑 보드가 어떤 입력을 받아서 JSON/SQLite/Next.js 렌더링으로 흘러가는지, 그리고 앞으로 원하는 “AI가 매일 상황을 보고 마켓 코멘트를 생성하는 단계”가 정확히 어디에 붙는지를 한 화면에 정리한 거야.

Agent / Cron / Prompt Node Scripts / Processing Storage / Canonical Data Web / Delivery AI Commentary Layer External Source

지금 구조의 핵심

  • cron이 에이전트 태스크를 트리거한다.
  • 에이전트는 캘린더/메일/뉴스를 모아 seed 또는 patch를 만든다.
  • Node 스크립트가 마켓 데이터, merge, 저장, 렌더용 메타 적재를 담당한다.

AI가 들어갈 정확한 위치

  • buildMarketPatch() 직후 또는 merge 직전에 붙이는 게 가장 자연스럽다.
  • 입력은 symbol, 가격, RSI, MA, 자산 역할, 필요 시 당일 뉴스 컨텍스트.
  • 출력은 statusTags, commentary, reflectionQuestion.

왜 이 방식이 좋은가

  • 숫자 계산은 안정적으로 유지된다.
  • 매일의 해석은 AI가 더 살아있게 만들어준다.
  • 웹은 저장된 결과만 렌더하므로 빠르고 일관된 UX를 준다.
